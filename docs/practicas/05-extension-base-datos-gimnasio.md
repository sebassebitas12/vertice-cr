# Extensión — Base de datos para gestión de gimnasio

- **Estado:** realizada y preparada para entrega, según informó Sebastián y las capturas compartidas.
- **Caso:** gestión de un gimnasio.
- **Fuente:** Trabajo de Extensión de Base de Datos.
- **Carácter:** práctica académica independiente del Laboratorio 2 y del sistema de Vértice CR.

## Objetivo

Diseñar y preparar una base de datos relacional para un gimnasio, ejecutarla en Supabase y reunir el diagrama y la evidencia para la entrega.

## Alcance observado

El proyecto `extension_gimnasio` de Supabase contiene nueve tablas en el esquema `public`: socios, entrenadores, credenciales, planes, membresías, clases, reservas, asistencias y pagos. Las capturas muestran registros de ejemplo y resultados del SQL Editor.

La carpeta de entrega se preparó con estos artefactos:

- Investigación en PDF.
- Diagrama entidad-relación en PNG.
- Script SQL.
- Captura de la ejecución en Supabase.

## Conceptos practicados

- Supabase administra el proyecto y ofrece herramientas para operar PostgreSQL; no es un motor de base de datos distinto.
- El diagrama entidad-relación ayuda a planear las entidades y relaciones antes de usar las tablas.
- El script SQL permite crear o preparar el esquema y cargar registros.
- El Table Editor y el SQL Editor sirven para inspeccionar los datos y evidenciar la ejecución.

## Relación con Vértice CR

La extensión retoma el diseño de bases de datos del Laboratorio 2. El caso de gimnasio es académico y se documenta como aprendizaje; sus tablas, datos y credenciales no forman parte del modelo ni de la aplicación de Vértice CR. La práctica tampoco establece por sí sola una decisión tecnológica para el producto.

Para el resumen de conceptos y la relación con el Laboratorio 2, consulta [la nota de aprendizaje de esta extensión](../aprendizaje/2026-10-22-extension-base-datos-gimnasio.md).
